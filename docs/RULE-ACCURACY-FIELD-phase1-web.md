# Phase 1 precision work: SEC-WEB-002 / SEC-WEB-005 / SEC-WEB-006

Baseline (docs/RULE-ACCURACY-FIELD-web-api-sc.md): strict field precision 4% (WEB-002), 8% (WEB-005), 32% (WEB-006). Confidence, profiles and severity are unchanged; the maintainer decides after measurement.

Tuning evidence: the earlier field doc, packages under `/usr/lib/python3/dist-packages` and `/usr/share/nodejs`, and synthetic analogues of reported SQLAlchemy/psycopg `text(f"...")` false positives. Paired cases: `fixtures/accuracy/web-api-sc-phase1-web/cases.json` (prefix `p1`). No pre-existing case was changed.

## Principle

A dynamic fragment is exempted only when local dataflow in the same file proves it is not attacker-influenced. Unknown things (function parameters, attributes, calls, imports, names never bound in the file, any binding that is not provably safe) stay "attacker-influenced" and are still reported. Python uses `ast` (`_PyFlow`); JS uses a literal-declaration registry (`JsConsts`). If a Python file does not parse, the old behaviour applies.

## Behaviour changes

### SEC-WEB-006 (Python only)
1. Interpolated fragments are not reported when every fragment is safe: literal; conditional / `or` of safe fragments; concatenation, `%`, `.format`, f-string of safe parts; `.join` over safe elements; names whose every binding in scope (function, then module) is safe, including `+=`/`.append` of safe items and `a, b = [], []`; literal-dict/list lookup (`{...}[k]`, `NAME[k]`, `.get(k, literal)`); `"?" * len(x)` placeholder lists; loop/comprehension variables over a closed source: literal collection, allowlist-filtered iteration (`for k in data if k in ALLOWED`, `& ALLOWED`), model field sets (`model_fields`, `__fields__`, `__table__.columns`...), catalog introspection (`get_table_names()`, queries on `information_schema`/`pg_tables`/`sqlite_master`). Covers the five reported patterns (conditional constant, constant where/cols fragments, closed-field SET lists, dict lookup, catalog/constant quoted identifiers).
   Cases: neg `p1web006-neg-*` (6), pos `p1web006-pos-*` (4).
   Recall risk: a constant that is later mutated through a path we do not model (`obj.attr`, `globals()`, `setattr`, in-place `d[k]=` on aliases) is treated as constant; an allowlist that is itself attacker-extensible is trusted; catalog names are trusted (a hostile table name in a double-quoted identifier containing `"` would be missed). Dynamic-key `d[k]=v` aliasing is not tracked.
2. `clean()` fix (shared by all rules): the closing `"""` of a multi-line triple-quoted value (`X = """ ... """`) was mistaken for a docstring start and blanked all following code up to the next triple quote. Now the body of such a value is kept and docstrings are still blanked. Cases: `p1clean-*` (3 neg, 2 pos). Effect: more code is scanned (recall up for every rule on Python files; it surfaced e.g. `exec('import %s' % module)` in ply and `os.system("mkdir %s" % path)` in twisted in the corpus, which are pattern-level hits as before). It also made a docstring example in typing_extensions vanish from WEB-006.

### SEC-WEB-005
3. Python `os.system/popen`, `subprocess(... shell=True)`, `eval`, `exec`: not reported when the command/code argument is safe by the same dataflow (constants, closed literal collections, literal-dict lookups). For shell sinks, `shlex.quote(x)` / `pipes.quote(x)` / `shlex.join` arguments are neutralised. Partial quoting (one quoted, one raw argument) is still reported. Cases: `p1web005-neg-python-constant-flow`, `-neg-shell-quoted-arguments`, `-pos-python-parameter-and-partial-quoting`. Recall risk: a constant string that is attacker-meaningful elsewhere is not an issue by itself; the risk is the same mutation-alias gap as above, and `shlex.quote` is trusted even when the shell interprets the quoted word in a second layer (`sh -c` nesting, ssh remote commands).
4. JS: `exec`/`execSync`/`eval`/`new Function` arguments whose every operand is a literal, number, or a `const`/single-assignment `let|var` bound to a literal (or literal table) are not reported; class method definitions `eval(expr) {` / `async exec(cmd) {` are not calls. Cases: `p1web005-neg-js-constants-and-method-definitions`, `p1web005-pos-js-request-values`. Recall risk: shadowing detection is regex-based (parameters, destructuring, loop/catch bindings detected; exotic scoping is not), so a const shadowed in an unusual way could hide a real sink.

### SEC-WEB-002
5. Operand-wise analysis replaces "any sanitiser word anywhere on the line suppresses". Each operand of the concatenation/template/ternary/`||` must be: literal, number, numeric expression (`.length`, `Number()`, `parseInt()`, `Math.*`, `.toFixed()`), known escaper/sanitiser (existing list plus `_.escape`, `he.encode/escape`, `encodeURIComponent`, `htmlEscape*`, `esc()`), a translation of a constant message (`t('k')`, `_('x')`, `gettext`, `i18n.t`, `$.i18n`, `chrome.i18n.getMessage`; all arguments literal), or a safe constant below. Cases: `p1web002-neg-escaped-numeric-translated-operands`, `-neg-ternary-of-safe-operands`, `-pos-partially-escaped-concatenation`, `-pos-query-data-and-translation-with-params`.
   Recall change (both directions): `'<td>' + escapeHtml(a) + b` was silently suppressed before and is now reported (recall up). Risk: `encodeURIComponent` is accepted for HTML text/attribute-value positions but it is not an escaper for `javascript:`/unquoted contexts; `\bsafe`/`trusted` name heuristic is unchanged.
6. Named constants: a name declared only with literal strings/templates (including multi-line templates) or a literal object/array table (`ICONS[name]`) is safe. Reassigned `let`/`var`, parameter shadowing, or a table with a non-literal value is still reported. Cases: `p1web002-neg-named-literal-template-and-table`, `p1web002-pos-reassigned-const-and-shadowed-and-table-with-variable`. This removes the four mkdocs `keyCodes[...]` hits from the field list. Recall risk: same regex-shadowing gap as item 4.
7. jQuery `.html()` is not a sink of this rule, so no change was needed for translated constants; the translation exemption above applies if such a sink is added.

## Corpus delta (dist-packages and /usr/share/nodejs; old vs new code)
* WEB-002: 14 -> 10 (4 mkdocs static-map lookups removed). JS under /usr/share/nodejs unchanged (18/24 findings identical).
* WEB-006: 29 -> 28 (removed: nltk constant table name, wapiti constant regexp f-string, typing_extensions docstring; added 2 impacket concatenations that the `clean()` fix un-hid, both genuine TP-opt).
* WEB-005: 68 -> 70 (removed 6: numpy f2py eval of join over generated names, reportbug and speechd `shlex.quote`d popen/system, sympy fixed-dict eval; added 8 un-hidden by the `clean()` fix, mostly `exec('import %s' % x)` / `os.system("ls %s" % x)` pattern hits). Net WEB-005 precision gain is limited: remaining findings are the TP-opt library patterns the earlier doc says need real taint analysis.
* Not measured here: precision on application code with SQLAlchemy `text()`; synthetic cases only.
